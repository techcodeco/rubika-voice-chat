01

معرفی

Rubika Voice Chat یک کتابخانهٔ Node.js است که فقط روی Voice Chat روبیکا تمرکز دارد. API عمومی آن متدهای سیشن، اتصال WebRTC، شرکت‌کنندگان، ترک‌های صوتی، پخش موسیقی و ضبط را ارائه می‌دهد؛ این کتابخانه SDK عمومی پیام‌رسانی نیست.

نکتهٔ معماری

برای اتصال عمومی فقط groupGuid لازم است. مقدار داخلی voice_chat_id توسط کتابخانه از API روبیکا resolve می‌شود و لازم نیست آن را دستی پیدا کنید.

Voice Chat

Join، Leave، Mute، Unmute، درخواست صحبت و تنظیمات.

Participants

گرفتن صفحه‌ای یا کامل فهرست شرکت‌کنندگان.

Streaming Recorder

ساخت فایل از شروع ضبط و افزودن تدریجی فریم‌ها.

Music Player

صف پخش، Seek، سرعت 0.5x تا 2x و ولوم.

02

پیش‌نیازها

  • Node.js نسخهٔ 22.5+؛ نسخهٔ پیشنهادی برای محیط پایدار Node 22.x است. پشتیبانی کامل Native WebRTC روی Node 26 هنوز در ماتریس رسمی وابستگی @roamhq/wrtc تأیید نشده است.
  • FFmpeg در PATH سیستم یا مسیر قابل تنظیم با ffmpegPath.
  • Encoderهای libopus برای OGG و libmp3lame برای MP3.
  • وابستگی Native مربوط به @roamhq/wrtc که در این نسخه برای Node 22 هدف‌گذاری شده است.
  • اتصال شبکهٔ خروجی و دسترسی UDP لازم برای WebRTC.
node -v
ffmpeg -version
ffmpeg -encoders

در ویندوز می‌توانید FFmpeg را با دستور زیر نصب کنید:

winget install --id Gyan.FFmpeg -e
03

نصب و احراز هویت

npm install rubika-voice-chat

روش پیشنهادی: سیشن نام‌دار

const { VoiceClient } = require('rubika-voice-chat');
const client = new VoiceClient('my-session');

client.on('session:created', () => console.log('Session created'));
client.on('session:loaded', () => console.log('Session loaded'));
client.on('error', error => console.error(error));

await client.start();

در اجرای نخست، در صورت نبود سیشن، کتابخانه شماره و کد ورود را از CLI دریافت می‌کند. اگر روبیکا وضعیت SendPassKey برگرداند، راهنمای data.hint_pass_key داخل پرانتز کنار درخواست گذرواژه نمایش داده می‌شود و گذرواژهٔ واردشده به‌عنوان pass_key در درخواست بعدی sendCode ارسال می‌شود. در صورت InvalidPassKey دوباره گذرواژه درخواست می‌شود. اگر signIn وضعیت CodeIsInvalid بدهد کد دوباره پرسیده می‌شود؛ برای CodeIsUsed ابتدا کد تازه درخواست می‌شود. وضعیت‌های اختصاصی ورود از data.status خوانده می‌شوند، نه فقط از وضعیت بیرونی پاسخ؛ بنابراین در شاخهٔ SendPassKey نبودن phone_code_hash خطا محسوب نمی‌شود.

registerDevice فقط هنگام ایجاد سشن جدید اجرا می‌شود. بارگذاری سشن ذخیره‌شده، حتی پس از تغییر نسخهٔ برنامه، باعث ثبت مجدد دستگاه نخواهد شد. پس از ورود و ثبت دستگاه، اطلاعات سشن در SQLite رمز‌شده ذخیره می‌شود.

اگر selfObjectGuid از قبل تنظیم نشده باشد، کتابخانه برای شناسایی حساب فعلی از getUserInfo با ورودی { user_guid: undefined } استفاده می‌کند و مقدار data.user.user_guid را می‌خواند.

روش مستقیم: auth و private key

const client = new VoiceClient(
  process.env.RUBIKA_AUTH,
  process.env.RUBIKA_PRIVATE_KEY_B64,
  { selfObjectGuid: process.env.RUBIKA_SELF_OBJECT_GUID }
);
await client.start();

کلید خصوصی می‌تواند PEM یا Base64 از JSON دارای version و d باشد. در حالت مستقیم، مقدار auth خامی را بدهید که از منبع معتبر خود دریافت کرده‌اید. برای امکان بازیابی خودکار سیشن پس از NOT_REGISTERED، از سیشن نام‌دار استفاده کنید.

شکل سوم سازنده

const client = new VoiceClient({
  auth: process.env.RUBIKA_AUTH,
  privateKeyB64: process.env.RUBIKA_PRIVATE_KEY_B64,
  selfObjectGuid: process.env.RUBIKA_SELF_OBJECT_GUID,
  sessionName: 'persisted-direct-session'
});

شروع سریع

const { VoiceClient } = require('rubika-voice-chat');

async function main() {
  const client = new VoiceClient('my-session');
  client.on('error', console.error);
  client.on('voice-chat:joined', e => console.log('Joined', e.groupGuid));
  client.on('recording:file-created', e => console.log('File:', e.output));

  await client.start();
  await client.joinVoiceChat('GROUP_GUID');

  const people = await client.getAllParticipants();
  console.log(people);

  await client.play('./music.mp3');
  await client.setPlaybackSpeed(1.25);

  await client.close(); // ضبط فعال را هم نهایی می‌کند.
}

main().catch(console.error);
05

اتصال و مدیریت Voice Chat

ورود به گروه

await client.joinVoiceChat('GROUP_GUID');
// نام جایگزین:
await client.connect('GROUP_GUID');

برای اتصال، فقط GUID گروه را به کتابخانه می‌دهید. کتابخانه شناسهٔ داخلی voice_chat_id را از API روبیکا دریافت و در همان کلاینت نگهداری می‌کند. لازم نیست آن شناسه را برای ترک ویس‌چت یا ضبط دوباره ارسال کنید.

گزینه نوع پیش‌فرض توضیح
createIfMissing boolean true اگر Voice Chat موجود نباشد، آن را ایجاد کند.
session object {} گزینه‌های شروع/ورود سیشن که به start() داده می‌شوند. 
await client.joinVoiceChat('GROUP_GUID', { createIfMissing: false });

کنترل میکروفون

await client.mute();
await client.unmute();
await client.requestSpeak();

ترک یا پایان Voice Chat

// خروج از Voice Chat فعلی؛ بدون ارسال chatGuid یا voiceChatId
await client.leaveVoiceChat();

// disconnect نیز به‌صورت پیش‌فرض از ویس‌چت خارج می‌شود
await client.disconnect();

// پایان‌دادن به خود Voice Chat گروه، نه فقط اتصال محلی
await client.discardVoiceChat();

// در پایان برنامه همهٔ منابع آزاد و ضبط فعال finalize می‌شود
await client.close();
شناسه‌ها به‌صورت داخلی مدیریت می‌شوند

هنگام خروج، خود کتابخانه جفت chat_guid و voice_chat_id ذخیره‌شده را به API روبیکا ارسال می‌کند. برای ترک اتصال نیازی به کپی یا واردکردن شناسهٔ ویس‌چت نیست. discardVoiceChat() خود Voice Chat گروه را پایان می‌دهد و ممکن است به سطح دسترسی مدیریتی نیاز داشته باشد.

06

مدیریت یک ویس‌چت در هر کلاینت

بر اساس محدودیت API روبیکا، هر نمونهٔ VoiceClient فقط یک Voice Chat فعال را نگهداری می‌کند. همهٔ اجزای WebRTC، Player، صف موسیقی، Recorder و Updateها به همان اتصال واحد تعلق دارند. تلاش برای ورود به گروه دیگر قبل از ترک گروه فعلی با خطای واضح متوقف می‌شود. 

// اتصال اول
await client.joinVoiceChat('GROUP_GUID_1');
await client.play('./music-room-1.mp3');

// برای تغییر گروه، ابتدا اتصال فعلی را ترک کنید
await client.leaveVoiceChat();

// سپس به گروه بعدی متصل شوید
await client.joinVoiceChat('GROUP_GUID_2');
await client.play('./music-room-2.mp3');
بدون شناسه هنگام خروج و ضبط

GUID گروه فقط هنگام joinVoiceChat(groupGuid) لازم است. پس از اتصال، همهٔ متدهای Player و ضبط از Context فعلی استفاده می‌کنند؛ leaveVoiceChat()، startRecording()، stopRecording() و setRecordingFilter() هیچ شناسهٔ گروه یا ویس‌چتی نمی‌گیرند.

07

فهرست شرکت‌کنندگان

دریافت شرکت‌کنندگان

// دریافت یک صفحه؛ در صورت وجود ادامه، next_start_id را به صفحه بعد بدهید.
const page = await client.getParticipants();
console.log(page.participants, page.has_continue, page.next_start_id);

// دریافت تمام صفحه‌ها تا انتها:
const all = await client.getAllParticipants();

// API یکپارچه؛ پیش‌فرض همه شرکت‌کنندگان را برمی‌گرداند:
const participants = await client.getVoiceChatParticipants();
// فقط یک صفحه:
const firstPage = await client.getVoiceChatParticipants({ all: false });

ساختار اشیای participant همان ساختاری است که API روبیکا برمی‌گرداند؛ فیلدهای شناسه، وضعیت و اطلاعات کاربر ممکن است با توجه به پاسخ سرور متفاوت باشند. فهرست شرکت‌کنندگان صرفاً برای مشاهده و مدیریت است و روی ضبط صدا فیلتر فردی اعمال نمی‌کند.

ضبط فقط به‌صورت کلی

قابلیت ضبط انتخابی افراد، Allow-list، Block-list و نگاشت دستی Track به GUID از API عمومی حذف شده است. ضبط‌کننده تمام صدای دریافتی ویس‌چت را میکس می‌کند و تنها امکان انتخاب اضافه‌شدن یا نشدن صدای خروجی Player با includeSelf وجود دارد.

08

ضبط تمام صدای ویس‌چت

ضبط‌کننده تمام فریم‌های صوتی Remote ویس‌چت را در میکسر PCM مشترک جمع می‌کند و با یک Encoder به یک فایل OGG/Opus یا MP3 می‌نویسد. فایل مقصد از آغاز ضبط ساخته می‌شود؛ فایل نهایی پس از توقف و finalize قابل‌پخش است.

ضبط همهٔ صداهای Remote

await client.startRecording({
  output: './recordings/voice-chat.ogg',
  format: 'ogg',
  includeSelf: false,
  consentConfirmed: true
});

در این حالت تمام صدای دریافتی از اعضای ویس‌چت داخل یک فایل میکس می‌شود. برای ضبط گروه دیگری لازم نیست شناسه وارد کنید؛ کلاینت فقط یک ویس‌چت فعال دارد و ضبط‌کننده به همان اتصال فعلی متصل است.

افزودن صدای self به همان فایل

await client.startRecording({
  output: './recordings/voice-chat-with-self.ogg',
  format: 'ogg',
  includeSelf: true,
  consentConfirmed: true
});

includeSelf: true صدای خروجی Player همین کتابخانه را با صدای تمام اعضای Remote در همان فایل ادغام می‌کند. مقدار پیش‌فرض false است. هیچ فایل جداگانه‌ای با نام self ساخته نمی‌شود. self در این API فقط صدای خروجی Player کتابخانه است؛ صدای میکروفون فیزیکی سیستم را ضبط نمی‌کند.

تغییر includeSelf در حین ضبط

// شروع ضبط بدون صدای self
await client.startRecording({
  output: './recordings/live-mix.ogg',
  includeSelf: false,
  consentConfirmed: true
});

// از این لحظه صدای Player هم به همان فایل اضافه شود
client.setRecordingFilter({ includeSelf: true });

// از این لحظه صدای Player از میکس کنار گذاشته شود
client.setRecordingFilter({ includeSelf: false });

// توقف و finalize فایل
await client.stopRecording();

نام setRecordingFilter برای سازگاری API حفظ شده، اما دیگر فیلتر شرکت‌کننده ندارد و تنها گزینهٔ معتبر آن includeSelf است. این متد فقط هنگام ضبط فعال قابل استفاده است. تغییر آن در میانهٔ ضبط بر فریم‌های بعدی اثر می‌گذارد.

گزینه‌های شروع ضبط

پارامتر نوع پیش‌فرض شرح
output string خودکار مسیر فایل نهایی؛ پوشه در صورت نیاز ساخته می‌شود.
format 'ogg' | 'mp3' از پسوند یا ogg فرمت خروجی. اگر پسوند مسیر با فرمت مغایر باشد خطا می‌دهد.
includeSelf boolean false صدای خروجی Player را در همان فایل میکس کند یا نکند.
consentConfirmed boolean false برای شروع باید صریحاً true باشد.
finalizeOnProcessExit boolean true هنگام SIGINT/SIGTERM ضبط را graceful finalize کند.

ضبط و تغییر تنظیمات

// متد جایگزین با نام صریح‌تر؛ همان ضبط همهٔ صداهای ویس‌چت
await client.startAllParticipantsRecording({
  output: './recordings/everyone.mp3',
  format: 'mp3',
  includeSelf: false,
  consentConfirmed: true
});

client.on('recording:file-created', e => console.log('File opened:', e.output));
client.on('recording:progress', e => console.log(e.framesCaptured, e.mixedFrames));
client.on('recording:filter-changed', e => console.log('includeSelf:', e.includeSelf));
client.on('recording:no-audio', e => console.warn('No audio frames received'));
client.on('recording:stopped', e => console.log('Finalized:', e.output));

const files = client.getRecordingFiles();
await client.stopRecording();

startAllParticipantsRecording() فقط alias متد startRecording() است و همان رفتار و همان مقدار پیش‌فرض includeSelf: false را دارد. گزینه‌هایی مثل source، includeParticipants، excludeParticipants، trackId و شناسه‌های گروه/ویس‌چت دیگر پشتیبانی نمی‌شوند و در صورت ارسال خطای TypeError دریافت می‌کنید.

فرمت و رفتار استریم

  • فایل مقصد از آغاز ضبط به‌صورت placeholder ساخته می‌شود؛ فریم‌های همهٔ اعضای Remote و در صورت فعال‌بودن self در میکسر جمع می‌شوند و یک FFmpeg encoder خروجی را می‌سازد.
  • فایل OGG/MP3 ممکن است تا توقف ضبط و finalize قابل پخش نباشد؛ فقط فایل نهایی پس از بستن encoder قابل اتکاست.
  • تمام صدای دریافت‌شده در یک فایل واحد قرار می‌گیرد؛ فایل جداگانهٔ self یا فایل مجزا برای افراد ساخته نمی‌شود.
  • برای فایل نهایی یک metadata با پسوند .json ساخته می‌شود.
  • stopRecording() ورودی FFmpeg را می‌بندد و metadata نهایی را می‌نویسد.
  • در خروج عادی با client.close() یا دریافت SIGINT/SIGTERM، کتابخانه ضبط فعال را نهایی می‌کند.
  • قطع برق، کرش سیستم، SIGKILL یا process.exit() اجباری فرصت finalize نمی‌دهد.
رضایت و حریم خصوصی

ضبط فقط با رضایت روشن شرکت‌کنندگان انجام شود. consentConfirmed: true تأیید مسئولیت برنامه‌نویس است و جایگزین اخذ رضایت واقعی نیست. قوانین محلی مربوط به ضبط مکالمات را رعایت کنید.

10

مرجع متدهای عمومی VoiceClient

تمام متدهای زیر مستقیماً روی شیء client در دسترس هستند. این نسخه عمداً فقط یک Voice Chat فعال را در هر نمونهٔ کلاینت مدیریت می‌کند.

متدهای EventEmitter

از آنجا که VoiceClient از EventEmitter نود ارث‌بری می‌کند، متدهای استاندارد on، once، off، removeListener، removeAllListeners، emit، listenerCount و eventNames نیز در دسترس هستند.

سازنده و سیشن

new VoiceClient(sessionName, options?)

ساخت کلاینت با نام سیشن.

new VoiceClient(auth, privateKeyB64OrPem, options?)

ساخت کلاینت با اعتبارنامهٔ مستقیم.

new VoiceClient({ auth, privateKeyB64, ...options })

ساخت کلاینت با آبجکت تنظیمات.

start(options?: object): Promise<VoiceClient>

آماده‌سازی API و بارگذاری یا ایجاد سیشن.

deleteSession(name?: string): boolean

حذف سیشن نام‌دار از ذخیره‌ساز محلی.

close(): Promise<void>

توقف ضبط، خروج از ویس‌چت فعلی و آزادسازی Player و ذخیره‌ساز.

اتصال و کنترل Voice Chat

joinVoiceChat(groupGuid: string, options?: object): Promise<JoinResult>

ورود به یک گروه؛ تنها متدی که به GUID گروه نیاز دارد. شناسهٔ ویس‌چت داخلی ذخیره می‌شود.

connect(groupGuid: string, options?: object)

نام جایگزین joinVoiceChat.

leaveVoiceChat(): Promise<object>

خروج از ویس‌چت فعال بدون نیاز به شناسه؛ کلاینت جفت شناسه‌های داخلی را به API روبیکا می‌فرستد.

mute(): Promise<boolean> · unmute(): Promise<boolean>

Mute و Unmute حساب جاری.

requestSpeak(): Promise<object>

ارسال درخواست اجازهٔ صحبت.

muteParticipant(participantObjectGuid: string): Promise<object> · unmuteParticipant(participantObjectGuid: string): Promise<object>

مرجع رویدادها

همهٔ رویدادهای سطح‌بالا با client.on(name, callback) قابل دریافت هستند. رویدادهای colon-style نام اصلی و رویدادهای خط‌تیره‌ای alias سازگاری‌اند. رویداد client-event همهٔ رویدادهای سطح‌بالایی را که از مسیر انتشار داخلی عبور می‌کنند، با payload یکپارچه و timestamp تحویل می‌دهد؛ فریم‌های خام صوتی و رویدادهای خام ترک را مستقیماً با نام رویداد خودشان دریافت کنید. 

client.on('client-event', event => {
  console.log(event.timestamp, event.event, event);
});

تنظیمات

تنظیمات را می‌توان در سازنده با { config: { ... } } یا از طریق متغیرهای محیطی فایل .env وارد کرد. مقادیر حساس مانند auth و private key را در مخزن عمومی قرار ندهید.

بخش کلیدهای مهم توضیح
API api.auth، api.privateKeyB64، api.client.app_version اعتبارنامه و مشخصات نسخهٔ کلاینت روبیکا.
Session session.name، session.databasePath، session.keyFilePath، session.encryptionKey ذخیره‌سازی محلی سیشن رمز‌شده.
Voice voice.iceTimeoutMs، voice.autoUnmute، voice.sendActivity، voice.activityIntervalMs تنظیم اتصال و رفتار Voice Chat.
Audio audio.ffmpegPath، audio.recordingDir، audio.keepRaw، audio.frameMs مسیر FFmpeg، پوشه ضبط و پارامترهای Player/Recorder.

فهرست مقادیر پیش‌فرض و نمونهٔ کامل را در فایل .env.example ریشهٔ پروژه ببینید.

فعال یا غیرفعال‌کردن Logها

کلاس عمومی کتابخانه VoiceClient است. می‌توانی هنگام ساخت نمونهٔ آن لاگ‌های داخلی را خاموش یا سطح آن‌ها را مشخص کنی. این گزینه فقط خروجی Logger داخلی را کنترل می‌کند؛ رویدادهای EventEmitter همچنان ارسال می‌شوند. 

const client = new VoiceClient('my-session', {
  logging: false // بدون لاگ داخلی کتابخانه
});

// یا با سطح مشخص:
const verboseClient = new VoiceClient('debug-session', {
  logging: true,
  logLevel: 'debug' // debug | info | warn | error
});
const directClient = new VoiceClient(auth, privateKeyB64, { logging: false });

همچنین logs: false و logger: false alias خاموش‌کردن لاگ هستند. در صورت ارسال شیء سفارشی logger، همان logger سفارشی استفاده می‌شود و بر گزینهٔ خاموش‌کردن پیش‌فرض اولویت دارد.

محدودیت‌ها و نکات فنی

  • در هر نمونهٔ VoiceClient فقط یک Voice Chat می‌تواند فعال باشد. برای تغییر گروه، ابتدا leaveVoiceChat() را اجرا کنید.
  • ضبط شامل تمام صدای Remote دریافتی است؛ امکان Allow-list، Block-list یا ضبط یک شرکت‌کنندهٔ مشخص وجود ندارد.
  • includeSelf فقط صدای خروجی Player کتابخانه را کنترل می‌کند، نه میکروفون فیزیکی سیستم.
  • فایل استریم در خروج graceful و سیگنال‌های SIGINT/SIGTERM نهایی می‌شود؛ خاموشی ناگهانی یا SIGKILL امکان finalize را از بین می‌برد.
  • خروجی OGG/MP3 پس از توقف graceful و بسته‌شدن encoder فایل نهایی قابل‌پخش است؛ فایل در حین ضبط الزاماً قابل‌پخش نیست.
  • تست‌های محلی جایگزین آزمایش با حساب و Voice Chat واقعی روبیکا نیستند؛ رفتار سرور و دسترسی حساب می‌تواند اثرگذار باشد.

عیب‌یابی

خطای FFmpeg یا ساخته‌نشدن فایل

خروجی ffmpeg -version و ffmpeg -encoders را بررسی کنید. مسیر باینری را در audio.ffmpegPath قرار دهید و مجوز نوشتن پوشه ضبط را کنترل کنید.

فایل خروجی خالی یا بدون صدای قابل پخش است

مطمئن شوید پس از اتصال موفق به ویس‌چت، فریم‌های صوتی دریافت می‌شوند و در زمان پایان، await client.stopRecording() یا await client.close() اجرا شده است. در صورت عدم دریافت فریم، فایل placeholder همراه metadata با status: no-audio باقی می‌ماند و رویداد recording:no-audio ارسال می‌شود.

چگونه self را وسط ضبط فعال یا غیرفعال کنم؟

در زمان ضبط، client.setRecordingFilter({ includeSelf: true }) صدای خروجی Player را به میکس اضافه می‌کند و مقدار false آن را از فریم‌های بعدی کنار می‌گذارد. این متد فقط همین گزینه را می‌پذیرد.

چرا نمی‌توانم به گروه دوم وصل شوم؟

هر نمونهٔ VoiceClient فقط یک ویس‌چت فعال دارد. ابتدا await client.leaveVoiceChat() را اجرا کنید و سپس با await client.joinVoiceChat('OTHER_GROUP_GUID') به گروه بعدی وارد شوید.

فایل OGG در حین ضبط سریع رشد نمی‌کند

فایل مقصد ممکن است تا توقف ضبط و finalize placeholder یا ناقص باشد. پس از await client.stopRecording() آن را با ffprobe بررسی کنید.

بعد از پایان برنامه فایل نهایی نشده است

از await client.close() استفاده کنید یا اجازه دهید برنامه SIGINT/SIGTERM را graceful دریافت کند. process.exit()، SIGKILL، crash سیستم و قطع برق قابل نهایی‌سازی تضمین‌شده نیستند.

رمز دومرحله‌ای، CodeIsInvalid یا CodeIsUsed

راهنمای hint_pass_key در پرانتز کنار درخواست گذرواژه نمایش داده می‌شود. اگر رمز اشتباه باشد وضعیت InvalidPassKey باعث تکرار درخواست گذرواژه می‌شود. CodeIsInvalid یعنی کد ورود اشتباه است و دوباره پرسیده می‌شود؛ CodeIsUsed یعنی کد قبلاً مصرف شده و کتابخانه ابتدا با sendCode کد تازه می‌گیرد.

چرا registerDevice بعد از تغییر نسخه دوباره اجرا نمی‌شود؟

این رفتار عمدی است: ثبت دستگاه فقط هنگام ایجاد سشن جدید انجام می‌شود. سشن ذخیره‌شده در اجرای بعدی بازیابی می‌شود و صرف تغییر RUBIKA_APP_VERSION باعث ثبت دوبارهٔ دستگاه نخواهد شد.

NOT_REGISTERED و TOO_REQUESTS

در سیشن نام‌دار، NOT_REGISTERED باعث حذف سیشن منقضی و شروع مجدد ورود می‌شود؛ پس از ایجاد سشن جدید، registerDevice برای آن سشن جدید اجرا خواهد شد. TOO_REQUESTS فقط به‌عنوان rate-limit گزارش می‌شود و سیشن را حذف نمی‌کند.
